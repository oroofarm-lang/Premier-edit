# Premier Edit — פאנל UXP לפרמייר

זה Stage 2 (`docs/superpowers/specs/2026-07-30-stage2-live-panel-design.md`): פאנל שרץ *בתוך* פרמייר במקום לייצא XML ולייבא ידנית.

מה הוא עושה:
1. **קורא** מה פתוח כרגע בפרמייר (פרויקט + סיקוונס פעיל).
2. **מציג את החיתוך הפעיל** של הפרויקט שנבחר — הרגעים שנבחרו, הפרמיסה, ואם קיימות גרסאות שנוצרו לפרופילים אחרים (Reel/Post/YouTube) — מאפשר לעבור ביניהן בלחיצה.
3. **מאפשר לשפר את החיתוך בשיחה** — כותבים הוראה בעברית (או לוחצים על מספר רגע כדי להפנות אליו), רואים דיף (נשאר/הוסר/נוסף/הוזז) לפני שמשהו משתנה, ומחילים או מבטלים.
4. **טוען תוכנית עריכה מאושרת** מהאפליקציה המקומית (Next.js) — אותה תוכנית שה-XML היה מייצא.
5. **בונה סיקוונס חדש** בפרמייר לפי התוכנית — מייבא קבצים חסרים, חותך כל קליפ ל-in/out המתוכנן, וממקם אותו בזמן המדויק. אחרי אישור אחד מפורש.

שים לב: פעולות 2-3 (מעבר פרופיל, שליחת הוראת שיפור, החלה/ביטול טיוטה) משנות את החיתוך הפעיל, ולכן מנקות אוטומטית תוכנית בנייה שכבר נטענה — צריך ללחוץ **Load plan** מחדש לפני **Build sequence** כדי לבנות את הגרסה העדכנית.

## הרצה — לפי הסדר

### 1. להפעיל את האפליקציה על פורט 3002

הפאנל מצפה למצוא את האפליקציה ב-`http://localhost:3002` (מוגדר ב-`manifest.json` תחת `requiredPermissions.network.domains`, ובקבוע `APP_ORIGIN` ב-`build-sequence.js` — אם אתה משנה פורט, צריך לשנות בשני המקומות).

```bash
npm run dev -- -p 3002
```

### 2. להפעיל Developer Mode בפרמייר

פרמייר Pro → Settings → Plugins → Enable Developer Mode (ואז להפעיל את פרמייר מחדש).

### 3. לטעון את הפאנל

ב-**UXP Developer Tool** (אפליקציה נפרדת של אדובי; אם אינה מותקנת — מ-Creative Cloud Desktop → Stock & Marketplace → Developer Tools):

1. **Add Plugin** → לבחור את `premiere-panel/manifest.json`.
2. **Load** (או **Load & Watch** כדי שכל שינוי בקוד ייטען אוטומטית).
3. בפרמייר: **Window → UXP Plugins → Premier Edit**.

### 4. להשתמש

1. לפתוח בפרמייר את הפרויקט שאליו רוצים לבנות (הפאנל בונה סיקוונס **חדש** בתוך הפרויקט הפתוח — לא נוגע בסיקוונסים קיימים).
2. בפאנל: לבחור פרויקט מהרשימה → **Load plan**.
3. לעבור על רשימת הקליפים שמוצגת (שם קובץ, in/out במקור, מיקום בטיימליין).
4. **Build sequence** → יופיע דיאלוג אישור → **Build**.

## מה לצפות לראות

- למעלה: שם הפרויקט הפתוח בפרמייר + הסיקוונס הפעיל.
- אחרי Load plan: סיכום (`N clips · Xs · fps · רזולוציה`) ורשימת הקליפים.
- אחרי Build: סיקוונס חדש בשם `<שם הפרויקט> (Premier Edit)` נפתח אוטומטית, ולוג בתחתית הפאנל שמראה כל קליפ שהונח.
- **בסוף הלוג: שורת `Final layout` שאומרת מה באמת יושב על כל טראק** — למשל `Final layout — V1: 19 clip(s) · A1: 9 clip(s)`. זו קריאה חוזרת מהסיקוונס עצמו, לא סיכום של מה שהפאנל ניסה לעשות. אם מופיעה אחריה שורת `Warning` — נשאר שם חומר מיותר שצריך למחוק ביד, וכדאי לספר לי.
- כל שגיאה מוצגת בשורת ה-status למעלה, לא נעלמת בשקט.

## למה יש רק תמונה אחת וקול אחד — ולמה זה היה שבור

בפרמיר, וידאו ואודיו של אותו קליפ מגיעים **מקושרים (linked)**. ל-UXP אין פקודת
Unlink בכלל — נבדק על כל 4675 השורות של ה-`.d.ts`, אין `unlink`, אין `link`.
וגם אין דרך להניח רק וידאו או רק אודיו: `createOverwriteItemAction` תמיד מניח
את שני החצאים.

לכן הפאנל עושה ביד את מה שעורך היה עושה עם Unlink + Delete: מניח את שני
החצאים, שולח את החצי המיותר לטראק צדדי, ומוחק אותו. **התוצאה שאמורה להישאר
היא V1 עם שכבת התמונה ו-A1 עם הקול** — לא שתי תמונות ושני פסי קול לכל רגע.

הניקוי הזה נשבר בשתי דרכים, ושתיהן תוקנו רק אחרי שנמצא זבל אמיתי בטיימליין:

1. **ניקוי לפי מספר טראק קבוע.** מקור עם N ערוצי אודיו תופס N טראקים, אז הנחה
   נוחתת איפה שהיא נוחתת. עכשיו הפאנל **קורא מה יש בפועל** על כל טראק ומוחק כל
   מה שמחוץ למה שהחיתוך צריך.
2. **החזקת handles ישנים.** כל טרנזקציה מבטלת אובייקטים שנקראו לפניה, אז ניקוי
   של טראק אחד הפיל את הבא אחריו עם `"The script object is no longer valid."` —
   וזה הפיל את שאר הניקוי והשאיר את הכל על הטיימליין. עכשיו כל טראק מקבל handle
   טרי, וכישלון בטראק אחד לא עולה לאחרים.

## מה זה עוד לא עושה

- **החלקת אודיו בין חיתוכים.** התוכנית כן מחזיקה `audioInSec`/`audioOutSec` (פריימים עודפים לצורך זה), אבל ל-UXP אין API להוספת מעבר אודיו — נבדק מול ה-type definitions האמיתיים של `@adobe/premierepro` v26.3.0: קיים `TransitionFactory` לווידאו בלבד. הדרך שכן אפשרית היא keyframes של ווליום דרך `AudioComponentChain`, וזה עדיין לא מומש. **בינתיים, ייצוא ה-XML הוא הדרך היחידה לקבל קרוספייד אודיו אמיתי** (`KGAudioTransCrossFade3dB`).
- אין Chat Edit במובן של AutoEdit — פקודות בשפה חופשית שמבצעות פעולה ישירה על טיימליין חי בפרמייר. מה שיש הוא שיפור שיחתי על **מודל הבחירה** (ה-`Selection` בבסיס הנתונים), לפני שהוא נבנה בכלל — עדיין דרך **Load plan → Build sequence**, לא כתיבה חיה לטיימליין.
- אין "צור 3 פרופילים" מתוך הפאנל — זו קריאת LLM כפולה-משולשת שעדיפה בטאב דפדפן מלא; הפאנל רק עובר בין גרסאות שכבר נוצרו באפליקציה.
- אין אריזה/הפצה — טעינה ב-dev mode בלבד.
- **לא נבדק עדיין**: שהאירוע `change` של `sp-picker` (Spectrum) באמת יורה כשבוחרים פרויקט מהרשימה — זה מה שמפעיל את הצגת החיתוך/השיפור. אם הבלוקים "Active cut"/"Refine this cut" לא מופיעים אחרי בחירת פרויקט, זה החשד הראשון לבדוק.

## הערה על אמינות ה-API

כל קריאות ה-API נכתבו מול המקורות האמיתיים ולא בניחוש: הדוגמאות הרשמיות של אדובי ב-[AdobeDocs/uxp-premiere-pro-samples](https://github.com/AdobeDocs/uxp-premiere-pro-samples), וה-type definitions מ-`npm pack @adobe/premierepro@26.3.0` (4675 שורות `.d.ts`). זה מה שחשף שאין API למעברי אודיו, ואת החתימות הנכונות (`ClipProjectItem.cast()`, `createSetInOutPointsAction`, `SequenceEditor.getEditor().createOverwriteItemAction()`, וכל כתיבה חייבת לעבור דרך `project.lockedAccess()` + `project.executeTransaction()`).

**עדיין לא נבדק בפרמייר אמיתי** — זה השלב שממתין לך. שינויים בטיימליין עוברים כטרנזאקציה אחת, כך ש-Cmd+Z אחד מבטל את כל הבנייה.
