# PRD — עוזר עריכה חכם לפריימיר פרו (Premiere Editing Agent)

**סטטוס:** טיוטה ראשונה
**גרסה:** 0.1
**תאריך:** יולי 2026

---

## 1. חזון ותקציר

מערכת שמקבלת ממני הוראות בשפה טבעית (וגם שינויי פרמטרים ידניים), ומבצעת בפועל
פעולות עריכה בפרויקט Adobe Premiere Pro — החל מהרגע שאני מצביע לה על תיקיית חומרי
גלם ותיקיית אודיו, ועד לתוצר מוכן (או כמעט מוכן) לפרסום.

המערכת בנויה כצוות סוכנים מומחים (תמלול, בחירת תוכן, חיתוך, אודיו, צבע, כתוביות,
הרכבה, QC) שעובדים יחד על אותו חומר גלם, כאשר לי יש שליטה על נקודות עצירה
לאורך התהליך — לא ריצה עיוורת מקצה לקצה.

**קהל היעד לגרסה הזו:** אני, כעורך שעובד בפריימיר. המערכת היא כלי אישי בשלב זה
(לא מוצר לעורכים אחרים), אבל נבנה אותה בצורה נקייה מספיק כדי שאפשר יהיה להרחיב
בעתיד אם ירצה.

**סוגי פרויקטים:** תוכן סושיאל מדיה (רילס למסעדות/מוצרים) וגם פרויקטי חתונה/סרט
ארוך. **ה-MVP מתמקד רק בתוכן סושיאל מדיה** — חתונות וסרטים ארוכים נשארים כיעד
עתידי מוצהר, לא חלק מהגרסה הראשונה.

## 2. הכרעות ארכיטקטורה מרכזיות

### 2.1 איך המערכת נוגעת בפריימיר בפועל

הוחלט: **פאנל UXP** הוא היעד, אבל **ה-MVP הטכני מתחיל מקובץ טיימליין** (ייצוא
FCP7 XML / OTIO שמיובא ידנית לפריימיר או דרך סקריפט קטן).

הסיבה לשלב הביניים: UXP-ל-פריימיר הוא API שעדיין מוגבל ומתפתח, ובניית עליו לפני
שהלוגיקה של "מה בכלל צריך לקרות בעריכה" מוכחת — מסוכן מבחינת זמן. קובץ טיימליין
נותן הוכחת ערך מהירה בלי תלות ב-API לא בשל.

**מסלול:**
- **שלב 1 (MVP):** המערכת מייצרת קובץ טיימליין (XML/OTIO) שמכיל את הסלקטים,
  הסדר, החיתוכים הגסים. אני מייבא אותו ידנית לפריימיר ומטייב.
- **שלב 2:** פאנל UXP בתוך פריימיר — רואה את הטיימליין החי, מאפשר לי לתת פקודות
  ("תקצר את הקליפ הזה ב-3 שניות") ולראות תוצאה מיידית בלי ייצוא/ייבוא ידני.
- **שלב 3 (עתידי, לא מחויב):** שכבת קריאה חוזרת מפריימיר — המערכת "רואה" גם
  שינויים ידניים שביצעתי, לא רק דוחפת שינויים.

### 2.2 היכן קורה העיבוד הכבד

עיבוד (ffmpeg, ניתוח וידאו, יצירת proxies) רץ **מקומית** על המחשב שלך, לא בתוך
פריימיר. פריימיר משמש בעיקר לתפירה הסופית ולעריכה הידנית שלך. תמלול יכול לרוץ
מקומית או בענן — תלוי בהחלטת פרטיות (ראה סעיף 7).

### 2.3 מלאי טכני נוסף על מה שסוכם בשלד

- מנוע תמלול בעברית — צריך הכרעה: Whisper (large-v3) מקומי, לעומת שירות ענן
  (Deepgram / ivrit.ai). **נקודה פתוחה — צריך בדיקת איכות בפועל על חומר שלך.**
- ffmpeg/ffprobe לניתוח מדיה וגנרציית proxies.
- ספריית ניתוח שמע לזיהוי הפסקות דיבור/קצב (לצורך edit-by-transcript).

## 3. פרופיל שימוש

- **סוגי תוכן:** רילס למסעדות ומוצרים, ובעתיד גם חתונות וסרטים ארוכים.
- **היקף חומר גלם טיפוסי:** עד כ-3 מצלמות + עד 2 מקורות אודיו נפרדים (מעבר
  לאודיו של המצלמות עצמן).
- **מבנה תיקיות קלט:** תיקיית חומרי גלם (וידאו) + תיקיית אודיו נפרדת.
- **שפה:** בעיקר עברית — משפיע ישירות על בחירת מנוע תמלול ועל טיפול RTL בכתוביות.
- **נכסי מיתוג קיימים:** כרגע אין (לא LUTs, לא טמפלייטים, לא ספריית מוזיקה) —
  המערכת תצטרך להציע ברירות מחדל סבירות ולתת לי לשמור מה שאני בוחר כ"סטייל
  קבוע" לפעם הבאה.

---

## 4. גבול האוטומציה (MVP)

**רמת האוטומציה בגרסה הראשונה:** אופציה א' — **Assembly גס בלבד**.

המשמעות: המערכת מזהה, בוחרת, וסודרת סלקטים לפי תמלול והיגיון (למשל: הטייק הכי
נקי, הרצף ההגיוני), אבל לא נוגעת בצבע, לא בפיניש סופי. אני עושה את הליטוש הסופי
ידנית בפריימיר.

**סיבה:** שינויים קטנים ונקודתיים מהירים יותר לביצוע ידני מאשר "לדבר" עם המערכת
עליהם. האוטומציה צריכה לחסוך את העבודה הכבדה (מיון שעות של חומר, בחירת טייקים,
סנכרון גס) — לא להחליף את מגע היד הסופי של עורך.

**נקודות עצירה לאישור** (במקום ריצה עיוורת מקצה לקצה):
1. אחרי ingest + תמלול → אישור שהכל זוהה נכון
2. אחרי בחירת תוכן/סלקטים → אני מאשר או מבצע שינויים קלים (למשל: "תוריד את
   הקטע הזה", "תעדיף את הטייק השני")
3. אחרי חיתוך גס → אישור לפני ייצוא הטיימליין

בכל שלב אפשר "תמשיך" או לתת תיקון ממוקד ולהמשיך משם — לא לחזור להתחלה.

**מה לא אוטומטי בכלל בשלב זה:** צבע, כתוביות שרופות סופיות, מיקס אודיו סופי —
כל אלה נשארים בידיים שלי בפריימיר, גם אם בעתיד ירצו להיכנס לפייפליין.

## 5. פלטים (MVP)

מיקוד ב-MVP: **תוצרי סושיאל מדיה בלבד.**

| פרופיל | יחס גובה-רוחב | אורך יעד | הערות |
|---|---|---|---|
| רילס/שורטס | 9:16 | עד ~60 שניות | כתוביות שרופות, פונט נבחר מראש |
| פוסט מוצר/מסעדה | 9:16 או 1:1 | 15–45 שניות | קצב מהיר, פתיח חזק ב-2 שניות ראשונות |
| גרסת יוטיוב/ארוך יותר | 16:9 | לפי תוכן | לשימוש עתידי, לא בהכרח ב-MVP הראשון |

**שורטים מהסרט הארוך — שתי דרכים, שתיהן נדרשות:**
1. חיתוך רגעים חזקים מתוך פרויקט ארוך קיים (highlight extraction).
2. הרכבה ישירה מחומר גלם גולמי, בלי תלות בפרויקט ארוך (למשל: תוכן שנועד מלכתחילה
   רק לרילס).

**כתוביות:** שרופות (burned-in), עם בחירת פונט/סטייל **מראש, לפני הרצה** (לא
דינמי לפי סרטון). תמיכה מלאה בעברית RTL.

## 6. הסוכנים (Agents)

רשימת בסיס + תוספות שזיהיתי כחסרות ביחס לצרכים שתיארת:

| סוכן | תפקיד | הערה |
|---|---|---|
| `ingest-agent` | סורק תיקיות חומר גלם + אודיו, ממפה קבצים, מריץ proxies | |
| `transcription-agent` | מתמלל בעברית, מסנכרן אודיו-וידאו | תלוי בהכרעת מנוע (סעיף 2.3) |
| `content-selection-agent` | בוחר טייקים/רגעים לפי בריף + איכות דיבור/פריים | ראה סעיף 6.1 |
| `cut-agent` | בונה רצף וקצב גס | |
| `audio-agent` | סנכרון מקורות אודיו, ניקוי בסיסי, לא מיקס סופי | |
| `captions-agent` | מייצר כתוביות שרופות לפי פונט/סטייל שנבחר מראש | |
| `assembly-agent` | מרכיב הכל לכדי טיימליין אחד לייצוא | |
| `qc-agent` | בדיקת שפיות: אורך תואם לפרופיל, אין חורים/חפיפות, סנכרון תקין | |
| `color-agent` | **לא ב-MVP.** נשאר מתועד לעתיד. | מחוץ לגבול האוטומציה שהוגדר בסעיף 4 |
| `style-memory-agent` *(חדש)* | לומד ושומר העדפות עריכה חוזרות (ראה סעיף 6.2) | |
| `broll-agent` *(חדש, מוצע)* | מזהה מתי חסר B-roll/כיסוי ומציע החלפה | שימושי לרילס מסעדות/מוצרים |

### 6.1 איך `content-selection-agent` בוחר תוכן

הגישה הפשוטה והנוחה ביותר להתחלה: **בריף קצר שאני כותב לפני הרצה** ("סרטון
על המנה החדשה, טון אנרגטי, קהל יעד צעיר, 30 שניות") + ניתוח סמנטי של התמלול
מול הבריף. לא מילות מפתח ידניות מדויקות, וגם לא "הבנה חופשית" בלי שום כיוון —
משהו באמצע: בריף חופשי בשפה טבעית שהמודל משתמש בו כמסגרת בחירה.

### 6.2 למידת סגנון לאורך זמן

מאושר כדרישה. המשמעות למודל הנתונים: לכל פרויקט/תיקון אני מבצע, המערכת שומרת
תבנית ("מעדיף קאטים קצרים יותר בפתיחה", "פונט X לרילס של מסעדות") בטבלה נפרדת
של העדפות, ומזינה אותה חזרה כהקשר לריצות עתידיות. זה משפיע ישירות על סכימת
ה-Prisma (טבלת `preferences` / `style_profile`).

## 7. פרטיות ותקציב — נקודות פתוחות שדורשות הכרעה

- **פרטיות:** האם מותר לשלוח קטעי אודיו/וידאו לשירותי תמלול/ניתוח בענן, או
  שהכל חייב לרוץ מקומית? זה קובע ישירות אם נבחר Whisper מקומי או שירות ענן.
  **טרם הוכרע — צריך תשובה לפני שממשיכים לשלב טכני.**
- **תקציב חודשי ל-API-ים:** לא הוגדר. משפיע על גודל מודל השפה שנשתמש בו
  לניתוח/בחירת תוכן, ועל בחירת מנוע תמלול.
- **מי בונה:** אתה + Claude Code. רמת ניסיון ב-TypeScript לא צוינה — כדאי לוודא
  לפני שממשיכים לשלב טכני, כדי לכייל כמה "תשתית מוכנה" מול "קוד לבנות ביחד".
- **לוח זמנים / דדליין:** לא הוגדר. אם יש פרויקט לקוח קונקרטי בטווח הקרוב, כדאי
  לדעת — זה יכול לשנות את סדר העדיפויות של השלבים.

## 8. ממשק משתמש

- צ'אט + תצוגת טיימליין ויזואלית + נגן פריוויו — לא צ'אט בלבד.
- שאיפה (לא MVP מיידי): שהאינטראקציה תתרחש בתוך פריימיר עצמו, לא רק בממשק
  Next.js חיצוני. זה בדיוק מה שפאנל UXP (שלב 2, סעיף 2.1) אמור לספק.
- **גרסאות:** נדרשת היסטוריית גרסאות עריכה עם אפשרות חזרה והשוואה. משפיע על
  מודל הנתונים — צריך טבלת `versions`/`edit_history` לא רק "מצב נוכחי".
- קלט קולי — לא נדרש בשלב זה; "לדבר איתו" הכוונה לצ'אט טקסטואלי.

## 9. שלבי פייפליין (MVP)

```
ingest → תמלול → בחירת תוכן (לפי בריף) → חיתוך גס → סנכרון אודיו
   → כתוביות (פונט קבוע מראש) → הרכבה → QC → ייצוא טיימליין (XML/OTIO)
   → ייבוא ידני לפריימיר → ליטוש ידני (צבע, מיקס, פיניש)
```

צבע ופיניש סופי **מחוץ לגבול האוטומציה** של הגרסה הזו (ראה סעיף 4).

## 10. מודל נתונים — קווי מתאר (לא סופי)

ישות | תיאור
---|---
`Project` | פרויקט עריכה בודד (רילס/סרטון), כולל פרופיל פלט יעד
`MediaAsset` | קובץ חומר גלם בודד (וידאו/אודיו), עם מטא-דאטה מ-ffprobe
`Transcript` | תמלול מקושר ל-`MediaAsset`, עם timestamps
`Selection` | טייק/קטע שנבחר על ידי `content-selection-agent`, עם ניקוד/סיבה
`Timeline` | רצף סופי שיוצא כ-XML/OTOI
`EditVersion` | תיעוד גרסה, מאפשר חזרה/השוואה
`StylePreference` | העדפות שנלמדו לאורך זמן (סעיף 6.2)
`ApprovalCheckpoint` | תיעוד נקודות העצירה שאושרו/תוקנו בכל ריצה

## 11. נקודות פתוחות שדורשות הכרעה לפני שממשיכים לשלב טכני

1. מנוע תמלול לעברית — Whisper מקומי מול שירות ענן (תלוי בהחלטת פרטיות).
2. מדיניות פרטיות סופית — מה מותר לשלוח לענן.
3. תקציב API חודשי.
4. רמת ניסיון ב-TypeScript / כמה תשתית "מוכנה" צריך Claude Code להכין לבד.
5. האם יש דדליין קונקרטי שמשנה סדר עדיפויות.
6. פורמט קובץ הטיימליין המדויק לשלב 1 — FCP7 XML או OTIO (יש לבדוק תאימות
   ייבוא בגרסת פריימיר שלך).

---

## 12. מפת דרכים (Roadmap) ברמת גובה

- **שלב 0 (בוצע):** שלד פרויקט, `.claude/` עם agents/skills/commands ריקים.
- **שלב 1 — MVP:** ingest → תמלול → בחירת תוכן → חיתוך גס → כתוביות → הרכבה →
  ייצוא XML/OTIO. פלט: רק תוכן סושיאל מדיה. אישור ידני בכל checkpoint.
- **שלב 2:** פאנל UXP בתוך פריימיר, אינטראקציה חיה, תיקונים נקודתיים בצ'אט.
- **שלב 3 (עתידי):** color-agent, פרויקטי חתונה/סרט ארוך, שכבת קריאה חוזרת
  מפריימיר, אפשרות הרחבה למוצר.
